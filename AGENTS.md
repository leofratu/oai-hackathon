# Repository writing instructions

Before writing or editing UI copy, documentation, submission text, release notes, or comments, read `docs/AI_WRITING_TROPES.md`.

Use plain, specific language. Prefer short concrete claims over dramatic framing. Do not add marketing filler, fake suspense, ornamental metaphors, or repetitive summaries. Avoid smart quotes and decorative Unicode in source text. Normal technical terms and established project names are fine.

These rules apply to human-facing prose. They do not require renaming APIs, code identifiers, schemas, or standard WebMCP terms.
